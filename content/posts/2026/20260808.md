最近在折腾 Android Studio 的环境配置，因为在github上发现了一个不错的开源软件，想fork一下魔改后自己用，之前其实已经安装过一次了，后面因为太重和不常用就清理了，这次重新装一下。

## 如何做到完美的环境隔离

Android 开发环境里，SDK、各种版本的构建工具、全局缓存、再加上动辄两三个 G 的模拟器镜像，默认配置下能轻松占C 盘几十个 G 的空间。所以配置之前尽量不要让 Android Studio 碰我们的 C 盘，我在 D 盘专门建立了一个 `D:\AndroidEnv` 文件夹。具体操作分为以下三步：

**1. 隔离 SDK 与模拟器下载目录**

打开 Android Studio，点击顶部菜单栏 `Tools` -> `SDK Manager`。在顶部的 `Android SDK Location` 右侧点击 Edit，将路径修改为你的 D 盘对应路径，例如 `D:\AndroidEnv\SDK`。以后下载的 Android 系统镜像和编译工具会存放到这。

**2. 隔离 Gradle 全局缓存**

点击 `File` -> `Settings` -> `Build, Execution, Deployment` -> `Build Tools` -> `Gradle`。将 `Gradle user home` 修改为 `D:\AndroidEnv\.gradle`。

**3. 系统环境变量**

按 `Win + S` 搜索并打开“编辑系统环境变量”，在“用户变量”中新建以下三个变量：

**1. `GRADLE_USER_HOME`**

*   **变量名：** `GRADLE_USER_HOME`
*   **变量值：** `D:\AndroidEnv\.gradle`

**2. `ANDROID_HOME`**

*   **变量名：** `ANDROID_HOME`
*   **变量值：** `D:\AndroidEnv\SDK`

**3. `ANDROID_USER_HOME`**

*   **变量名：** `ANDROID_USER_HOME`
*   **变量值：** `D:\AndroidEnv\.android`

## Gradle 与 JDK 版本不兼容

新建项目后，底部的 Build 控制台直接报错说The project's Gradle version 8.7 is incompatible with the Gradle JVM version 25...

经过查找资料发现当前项目使用的 Gradle 8.7 最高只支持到 Java 21，而 IDE 默认或者系统环境里抓取到了 Java 25。虽然 Android Studio 的图形界面提供了 `Apply compatible Gradle JDK configuration` 的快捷链接，但点击它毫无反应完全卡死，即使可以点击并修改，发现也没有起作用。

**解决方式：**

1. 下载一个免安装的纯净版 JDK 21（例如解压到 `D:\AndroidEnv\JDK21`）。

2. 打开项目根目录下的 `gradle.properties`，在文件末尾加上：

   ```properties
   org.gradle.java.home=D:/AndroidEnv/JDK21
   //注意：路径必须使用正斜杠/
   ```

如果你准备用终端执行 `.\gradlew` ，要在 Windows 环境变量中配置 `JAVA_HOME` 指向你的 JDK 21 目录，并把 `%JAVA_HOME%\bin` 加入到 `Path` 中，否则终端找不到 Java 环境。

## 一直卡在 `prepareKotlinBuildScriptModel`这里不动

重新 Sync，发现一直卡在 `> Task :prepareKotlinBuildScriptModel UP-TO-DATE` 没有动静了。

**1. 修改 Gradle Wrapper 彻底解决卡顿（知乎解法）**

打开项目目录下的 `gradle/wrapper/gradle-wrapper.properties`，将 `distributionUrl` 结尾的 `-bin.zip` 改为 `-all.zip`。为了加速，顺便将链接中的 `services.gradle.org` 替换成腾讯云的镜像源mirrors.cloud.tencent.com/gradle。

**2. 结束僵尸进程并重启**

打开终端运行 `gradlew --stop`，并重启 Android Studio，清理掉后台卡死的 Gradle 守护进程。

**3. 删掉多余的自动下载插件**

打开 `settings.gradle.kts`，找到并注释掉 `foojay-resolver-convention` 插件。这个插件会在后台尝试去海外服务器下载 JDK，因为网络原因会一直挂着且不报错。

```
plugins {
    // id("org.gradle.toolchains.foojay-resolver-convention") version "1.0.0"
}
```

**4. 注入国内镜像源**

同样在 `settings.gradle.kts` 中，在 `pluginManagement` 和 `dependencyResolutionManagement` 的 `repositories` 代码块**最顶端**，加入阿里云镜像：

```
maven { url = uri("[https://maven.aliyun.com/repository/google](https://maven.aliyun.com/repository/google)") }
maven { url = uri("[https://maven.aliyun.com/repository/public](https://maven.aliyun.com/repository/public)") }
```

## 快照文件脏数据

当网络墙和环境都搞定后，终端执行 `.\gradlew build` 报错：

> Execution failed for task ':app:parseDebugLocalResources'.
>
> Cannot snapshot output property 'outputDirectory'.

这是因为前面反复强杀卡死进程时，Gradle 在项目里留下了残缺的锁文件和脏的输出目录。

**解决办法：**

1. 在终端执行 `.\gradlew clean`。
2. 如果删不干净，手动去项目根目录删掉 `.gradle` 文件夹。
3. 删掉 `app/build` 文件夹。
4. 重启 Android Studio 后再次执行 `.\gradlew build`，大概率就会`BUILD SUCCESSFUL`了。

## 下载模拟器镜像（System Image）

最后在 Device Manager 创建模拟器时，列表里通常会出现两个长得很像的镜像。

- `Google Play Intel x86_64 Atom System Image` (标准版)
- `16 KB Page Size Google Play...` (特殊测试版)

一般只需要下载**标准版**即可。如果不小心下载了那个 16 KB Page Size 的版本会多占硬盘 2GB左右 的空间。如果不想要了可以去顶部的 **SDK Manager** -> 勾选右下角 **Show Package Details** -> 展开对应的 Android 版本，取消勾选那个 16 KB 的镜像并 Apply即可。

## 配置 Gradle 本地代理 (Proxy)

如果在前面替换了阿里云镜像、腾讯云镜像后，同步依然很慢或者不动，或者你在拉取某些没有在国内做镜像的第三方库时报错，那么可以尝试**直接给 Gradle 配置本地代理**。不过Android Studio 设置界面（Settings -> HTTP Proxy）里的代理应该管不住底层的 Gradle 编译进程，不放心可以在文件末尾加上你的本地代理端口配置，比如：

```properties
# HTTP 代理
systemProp.http.proxyHost=127.0.0.1
systemProp.http.proxyPort=7890
# HTTPS 代理
systemProp.https.proxyHost=127.0.0.1
systemProp.https.proxyPort=7890
```
